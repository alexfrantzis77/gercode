## Notebook cell structure (strict — Otter requires this order)

1. **Otter init (code)**
   ```python
   import otter
   grader = otter.Notebook("<notebook_name>.ipynb")
   ```

2. **Title (markdown)**
   ```markdown

   > **Alex Frantzis** <br> Cool Student >:3, UC Berkeley

   [![License](https://img.shields.io/badge/license-CC%20BY--NC--ND%204.0-blue)](https://creativecommons.org/licenses/by-nc-nd/4.0/)
   ***
   ```

3. **ASSIGNMENT CONFIG (raw) — optional**
   Only some notebooks have this (Mohrs_Circle, kmeans). Effective_Stress, Stress_Distribution, and Compaction do NOT include it. When present:
   ```yaml
   # ASSIGNMENT CONFIG
   solutions_pdf: false
   name: hw##
   files:
       - resources
   generate:
       pdf: false
       filtering: true
       pagebreaks: true
   check_all_cell: true
   requirements:
       - matplotlib==3.10.0
   export_cell:
       instructions: "Make sure you submit the .zip file to Gradescope."
       run_tests: false

       pdf: false
   ```

4. **Introduction (markdown)** — Topic background with equations, concepts, and engineering context. Often multiple markdown cells. Equations use LaTeX (`$$...$$`). May include images (`<center><img src="resources/..." width='650'/></center>`).

5. **Imports (code)** — Always marked "Please run this cell, and do not modify the contents":
   ```python
   import hashlib
   def get_hash(num):
       """Helper function for assessing correctness"""
       return hashlib.md5(str(num).encode()).hexdigest()

   import numpy as np
   import math
   import matplotlib.pyplot as plt
   import matplotlib.image as mpimg
   # (plus any other needed imports)
   ```

6. **Question blocks** — repeated for each question (see below).

7. **Optional non-graded demo cells** — additional visualizations or worked examples at the end.

## Solution cell conventions

### Variant A — Inline (most common)
Key answer lines are tagged `# SOLUTION` at end of line. The full function body is present; student-facing version replaces those lines with `...`.

```python
def myFunc(x, y):
    result = x + y  # SOLUTION
    return result
```

### Variant B — Block (when student gets a partial template)
The real answer lives inside `# BEGIN SOLUTION NO PROMPT` / `# END SOLUTION`.
The student template with `...` placeholders lives inside `""" # BEGIN PROMPT` / `"""; # END PROMPT`.
Both blocks appear in the same code cell.

```python
def myFunc(x, y):
    # BEGIN SOLUTION NO PROMPT
    result = x + y
    # END SOLUTION
    """ # BEGIN PROMPT
    result = ...
    """; # END PROMPT
    return result
```

## Test cell conventions

Every test cell opens with a config header:
```python
""" # BEGIN TEST CONFIG
points: 0
failure_message: Your function is getting some calculations wrong!
success_message: Function correctly calculates all test cases :D
""" # END TEST CONFIG

assert get_hash(...) == 'md5hashstring'
```

**First test in every question** — always checks the student ran their function (not left as `...`):
```python
""" # BEGIN TEST CONFIG
points: 0
failure_message: Make sure to test your function!
""" # END TEST CONFIG

assert get_hash(type(qN)) != '14e736438b115821cbb9b7ac0ba79034'
```
(`'14e736...'` is the MD5 of `<class 'ellipsis'>`)

### Hash encoding patterns
| Pattern | When to use |
|---|---|
| `get_hash(int(value))` | Integer result |
| `get_hash(np.round(value, N))` | Float rounded to N decimal places |
| `get_hash(int(10 * np.round(value, 1)))` | 1-decimal precision as integer |
| `get_hash(int(np.round(np.sum(array))))` | Array aggregate |
| `get_hash(int(np.round(np.mean(array))))` | Array aggregate |
| `np.isclose(result, expected, rtol=1e-2).all()` | Float array comparison (no hash) |

### Figure test patterns
```python
# Check plot data
assert get_hash(np.round(np.sum(fig.axes[0].get_lines()[0].get_xdata()), decimals=0)) == '...'
assert get_hash(np.round(np.sum(fig.axes[0].get_lines()[0].get_ydata()), decimals=0)) == '...'

# Check axis labels (case-insensitive word check)
assert all([word in fig.axes[0].get_xlabel().upper() for word in ['STRESS', 'KPA']])
assert all([word in fig.axes[0].get_ylabel().upper() for word in ['DEPTH', 'M']])

# Check axis limits
assert fig.axes[0].get_xlim() == (0, 1600)
assert fig.axes[0].get_ylim() == (-800, 800)
```

## Question design patterns observed across completed assignments

- **Warm-up / scaffold**: first question is simpler (scalar formula), later questions build on it
- **Array support**: functions accept both scalar and array-like inputs via `np.asarray()`
- **Layered soil**: `getStress`, `getPP`, `getEffStress` pattern — each question's function calls the previous one
- **Plotting questions**: always wrapped in a named function (e.g. `def createFigure():`) so tests can call it and inspect `fig.axes[0].get_lines()[N]`
- **Interpretation questions**: multiple-choice style (e.g. classify as 'A'/'B'/'C'/'D'), stored in a list `qN = ['A', 'B', ...]`
- **Reflection questions**: open-ended markdown cells at the end, not graded
